# Self-RAG：Linux 单卡 48GB 入门

本教程对应你的目标：先用作者数据跑通一次，再换自己的数据。

本次路线是 **在作者发布的 Self-RAG 7B 上做 QLoRA 继续微调**。基础模型已经学过反思标记，我们复用它的 tokenizer 和权重，只训练新增的 LoRA 参数。它能验证完整训练流程，但不是从 Llama-2 开始复现论文，也不能用作者训练数据上的继续训练结果证明模型优于原版。

教程假设使用一张支持 BF16 的 NVIDIA 48GB GPU，例如 A40、RTX A6000 或 RTX 6000 Ada。卡的具体型号会影响速度。不要仅按“48GB”选卡：老一代 GPU 的精度支持也可能不同。

## 1. 先理解这次到底在训练什么

原论文的训练链路：

```text
GPT-4 标注 Critic 数据 → 训练 Critic
                            ↓
原始问答 + 检索器 + Critic → 带反思标记的 Generator 数据
                            ↓
                      训练 Generator
```

这次作者已经提供了 Generator 数据和训练好的 Self-RAG 模型，所以从后半段入手：

```text
作者 Self-RAG 7B + 作者训练数据的小样本
                   ↓
             QLoRA 继续训练
                   ↓
           保存 adapter → 重新加载验证
```

训练的是“如何依据问题和证据，生成答案与反思标记”。检索器本身不在这个训练脚本里更新。模型输出 `[Retrieval]` 后，实际查库和插入文档仍由外部程序执行。

## 2. 准备云服务器

建议第一轮配置：

| 项目 | 本教程配置 |
|---|---|
| GPU | 单张 NVIDIA 48GB，支持 BF16 |
| 系统 | Linux，建议 Ubuntu 22.04 |
| Python | 3.10，独立 Conda 环境 |
| 系统内存 | 建议 32GB 以上，64GB 更宽裕 |
| 可用磁盘 | 建议 80GB 以上，包含环境、缓存与 checkpoint |
| 初次训练 | 2048 条训练数据，64 条验证数据，50 个优化步骤 |

QLoRA 减少的是加载后的显存开销。作者原始模型权重仍需下载，两个权重分片合计约 13.5GB；训练数据约 256MB。无需先下载全维基百科或 9GB 的检索演示语料。

在服务器终端先运行：

```bash
nvidia-smi
```

检查 GPU 型号与显存。首次先让一个进程使用一张卡。

## 3. 上传教程脚本，创建独立环境

把本文件所在文件夹内的 Python 文件与依赖文件上传到服务器工作目录，例如你的 home 下的 `selfrag-lab` 目录。可以使用云平台文件上传、SFTP 或 VS Code Remote SSH。后续命令都在该目录执行。

如果已经有 Conda：

```bash
conda create -n selfrag48 python=3.10 -y
conda activate selfrag48
cd ~/selfrag-lab
python -m pip install --upgrade pip
python -m pip install torch==2.5.1 --index-url https://download.pytorch.org/whl/cu121
python -m pip install -r requirements.txt
python -m pip check
```

这是为教程独立固定的一组版本，不是仓库原始环境的逐项复刻。这里仅安装训练与 Transformers 推理需要的库，不安装 vLLM、DeepSpeed 或单独编译的 flash-attn。

检查运行环境：

```bash
python -c "import torch; print('torch:', torch.__version__); print('CUDA available:', torch.cuda.is_available()); print('GPU:', torch.cuda.get_device_name(0)); print('BF16:', torch.cuda.is_bf16_supported())"
```

预期 CUDA available 和 BF16 都为 True。若失败，先修复 GPU 镜像、驱动或环境，暂时不要开始下载模型。云端预装环境如果版本混乱，使用这个新环境，避免与其已有 torchvision 等包混用。

## 4. 下载作者数据，抽取试跑样本

```bash
python prepare_data.py
```

预期输出：训练集 2048 条、验证集 64 条。随机种子固定为 42；训练集会排除与验证集完全相同的 instruction/input 问题，减少同一问题不同证据版本的泄漏。

这仍是从作者训练集里切出的流程验证数据，不能作为公开基准或独立泛化评估。

数据每行是一个 JSON 对象，核心字段如下（下面是用于讲解的自造样本，不是作者数据原文）：

```json
{"instruction":"What is the capital of France?","input":"","output":"[Retrieval]<paragraph>Paris is the capital of France.</paragraph>[Relevant]The capital of France is Paris.[Fully supported][Utility:5]"}
```

这些标记分别表达：

| 标记 | 含义 |
|---|---|
| `[Retrieval]` | 需要检索 |
| `[No Retrieval]` | 不需要检索 |
| `<paragraph>...</paragraph>` | 外部提供的证据内容 |
| `[Relevant]` / `[Irrelevant]` | 证据与问题是否相关 |
| `[Fully supported]` 等 | 回答是否受到证据支持 |
| `[Utility:1]` 至 `[Utility:5]` | 对回答有用性的等级评价 |
| `[Continue to Use Evidence]` | 后续段落继续使用已有证据 |

预处理会把问题和证据正文对应的 label 设为 -100，使它们不计入预测损失；它们仍参与模型的注意力计算。回答、反思标记和段落边界保留监督。

先核对数据处理：

```bash
python check_data.py
```

这里只需要下载 tokenizer，不下载 7B 权重。检查点：所有反思标记各自是一个 token；有监督目标的样本非零；展示的监督文本包含回答与反思标记，但不包含问题和证据正文。

## 5. 先确认作者模型能正常加载

```bash
export CUDA_VISIBLE_DEVICES=0
python infer.py
```

第一次会下载模型权重，然后用固定证据测试法国首都问题。可以看到回答及反思标记；输出措辞不保证逐字相同。

这个脚本是固定提供一段证据的生成检查，没有自动检索或论文里的多候选评分搜索。保存反思标记时使用 `skip_special_tokens=False`，否则你会误以为模型没有生成它们。

## 6. 启动第一次微调

```bash
python train_qlora.py --max-steps 50 --output-dir outputs/selfrag-qlora
```

脚本先计算验证损失，再训练 50 个优化步骤，最后计算训练后的验证损失并保存 adapter。验证阶段一开始不会出现训练进度，要先等待它完成。

配置的含义：

| 参数 | 值 | 作用 |
|---|---|---|
| 基础模型 | selfrag/selfrag_llama2_7b | 复用已有 Self-RAG 能力与词表 |
| 量化 | 4-bit NF4 + double quant | 降低基础权重的显存开销 |
| 计算精度 | BF16 | 适用于这次选择的 GPU |
| max length | 2048 | 问题、证据、回答的总 token 上限 |
| micro batch | 1 | 单次前向/反向的一条样本 |
| 梯度累积 | 8 | 单卡有效 batch 为 8 |
| LoRA rank | 16 | 学习低秩更新 |
| 学习率 | 1e-4 | 入门起点，需要后续验证调整 |
| max steps | 50 | 50 次优化器更新，不是 50 条数据 |

第一轮大致消耗 400 次训练样本展示，不会遍历完 2048 条。这里只是确认流程能跑通。

另开一个服务器终端观察显存：

```bash
watch -n 2 nvidia-smi
```

可选看 loss 曲线：

```bash
tensorboard --logdir outputs/selfrag-qlora --port 6006
```

通过云平台端口转发或 SSH 隧道访问 TensorBoard。loss 能正常计算、训练能完成、模型能保存，是这轮的检查目标；不要要求每个 step 都下降，也不要仅凭训练 loss 判断 RAG 效果。

## 7. 加载刚训练好的 adapter

```bash
python infer.py --adapter outputs/selfrag-qlora
```

与第 5 步对比的是同一个问题、证据和解码设置。adapter 目录不是完整 7B 模型，加载时仍需要作者基础模型。

输出目录中应包含适配器权重、适配器配置、tokenizer 文件，以及 before/after/train 的指标文件；训练 checkpoint 子目录还包含用于断点恢复的训练状态。

完整跑通的标准是：

1. 数据和 tokenizer 检查通过。
2. 模型加载成功，训练 loss 为有限数值。
3. 完成 50 步，写出 adapter。
4. 新进程能重新加载 adapter 并生成回答。
5. 能对比训练前后的验证损失，并知道它不等同于检索准确率或事实正确率。

这次的评估数据来自作者原始训练集，模型可能早就见过它，所以不能据此宣称“微调提升了模型”。

## 8. 再扩大数据，然后换成自己的数据

第一次成功后，单独准备大一点的数据子集：

```bash
python prepare_data.py --train-count 10000 --eval-count 500 --output-dir data10k
python train_qlora.py --train-file data10k/train.jsonl --eval-file data10k/eval.jsonl --max-steps -1 --epochs 1 --output-dir outputs/selfrag-10k
```

这会从作者基础模型开始新的一次训练，按 1 个 epoch 遍历训练集。不要把“继续使用作者模型微调”误读成它会自动接着前面 50 步训练。

要恢复同一次训练的状态，指定真实存在的 checkpoint，例如：

```bash
python train_qlora.py --max-steps 100 --output-dir outputs/selfrag-qlora --resume outputs/selfrag-qlora/checkpoint-50
```

这是恢复后把总优化步数目标提高到 100，不是额外再加 100；改变总步数会改变后续调度计划。

换成自己的数据时，使用 instruction/input/output 的 JSONL 结构，并在 output 中保留有依据的反思标记。问题、证据、答案及支持标签必须相互匹配；不要给所有样本机械添加 `[Fully supported][Utility:5]`。同时保留不需检索、无关证据、不支持回答等情况。

自己的数据量小时可人工构造和核对；规模变大时，再学习仓库里 Critic/检索器辅助标注的流程。真实独立验证集要与训练集按文档、主题或时间划分，避免同一文档换个问法就同时出现在两边。中文业务还需单独评估：作者原模型和数据主要面向英文。

## 常见卡点

| 现象 | 先检查什么 |
|---|---|
| CUDA 不可用 | 云镜像、驱动、当前 Python 环境和 GPU 是否已挂载 |
| BF16 不支持 | GPU 具体型号；本教程不要直接套到旧架构 GPU |
| 下载超时 / 认证失败 | 云机访问 Hugging Face 的网络和对应下载权限；先读具体错误 |
| 显存不足 | 是否有其他 GPU 进程、是否误开多个训练进程；再考虑把长度降到 1024 |
| 有效样本变少 | 过长的问题占满长度上限；用 check_data 检查，别忽略被截断的监督目标 |
| 回答看不到反思标记 | 解码时是否误用了 skip_special_tokens=True |
| 模型自己编造证据段落 | 先检查训练数据标签，以及证据正文是否被错误计入 loss；这也需要完整推理程序配合检索控制 |
